## 1. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Пользователь | Один, локально, без авторизации |
| Формат | Веб-приложение в браузере |
| Активы | Акции РФ, облигации РФ |
| Валюта | Только RUB |
| Портфелей | Один |
| Учет позиции | Текущее количество + средняя цена |
| Метод | Средневзвешенная стоимость |
| Дробные количества | Нет, целые |
| Комиссии и налоги | Не учитываются |
| Дивиденды по акциям | Только фактически полученные, вручную |
| Купоны по облигациям | Ожидаемые из MOEX + фактические вручную |
| Реинвестирование | Не учитывается, только доход |
| Котировки | Автоматически из MOEX |
| Импорт отчетов брокера | Не нужен |
| Корпоративные действия | Не нужны, кроме номинала/амортизации облигаций |
| Метрики | Стоимость, выплаченные дивиденды, выплаченные купоны, ожидаемые купоны, динамика стоимости |
| Срок | MVP как можно быстрее |

### Важное уточнение по доходам

- **Дивиденды акций:** в MVP только фактические выплаты. Ожидаемые дивиденды и прогнозы не делаем.
- **Купоны облигаций:** ожидаемый график остается, потому что MOEX отдает его бесплатно и точно. Если нужно убрать и его — этап 4 сократится примерно на полдня.
- Если ожидаемые купоны тоже не нужны, дашборд будет показывать только уже полученный доход.

## 2. Границы MVP

### Входит

- Один портфель.
- Поиск акций и облигаций РФ через MOEX ISS.
- Добавление актива в портфель.
- Операции покупки и продажи.
- Автоматический расчет количества и средней цены.
- Текущая цена и стоимость позиции.
- Ожидаемые купоны по облигациям из MOEX.
- Фактические дивиденды и купоны: ручное добавление/подтверждение.
- Дашборд: стоимость, вложено, выплаченный доход, ожидаемые купоны.
- График динамики стоимости портфеля.
- Обновление котировок при запуске и по расписанию.
- Резервная копия SQLite и экспорт данных.

### Не входит

- Ожидаемые дивиденды акций и любые прогнозы дивидендов.
- Парсинг сторонних сайтов.
- Несколько портфелей и переключатель портфелей.
- Авторизация и многопользовательский режим.
- Иностранные активы, крипта, валюта, недвижимость.
- Комиссии, налоги, НДФЛ.
- Реализованная прибыль, FIFO, XIRR, TWR.
- Импорт CSV/Excel/PDF от брокера.
- Сплиты, конвертации, mergers.
- Торговля и брокерские интеграции.
- Мобильное приложение (адаптивная верстка — да).

## 3. Архитектура

```text
Браузер
  Angular + PrimeNG + Chart.js
        │ REST /api
        ▼
  FastAPI (Python 3.12)
    ├── SQLAlchemy 2 + Alembic
    ├── SQLite (WAL)
    ├── httpx → MOEX ISS
    ├── APScheduler (обновление котировок)
    └── раздача собранного Angular в production
```

### Backend

- Python 3.12, FastAPI, Pydantic v2.
- SQLAlchemy 2.0, Alembic, SQLite.
- httpx для MOEX ISS, tenacity для retry.
- APScheduler: обновление при старте и раз в день после закрытия торгов.
- pytest.
- `uv` для зависимостей и запуска.

### Frontend

- Angular standalone components + signals.
- PrimeNG: таблицы, диалоги, календарь, dropdown, inputnumber, chart.
- Chart.js через PrimeNG Chart.
- Reactive Forms + валидация.
- Русский интерфейс, светлая тема.
- Dev: `ng serve` с proxy на FastAPI.
- Prod: `ng build`, FastAPI раздает `dist/browser`, fallback на `index.html`.

### Запуск

- `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000`.
- Приложение открывается на `http://127.0.0.1:8000`.
- `start.ps1` для Windows: сборка фронта при необходимости + запуск backend.

## 4. Модель данных

### `portfolio`

Одна запись, создается сидом.

- `id`
- `name`
- `base_currency` — RUB
- `created_at`

### `asset`

- `id`
- `secid` — тикер MOEX (SBER, SU26238RMFS4)
- `isin`
- `name`
- `type` — `STOCK` / `BOND`
- `board` — TQBR / TQCB
- `currency` — RUB
- `face_value` — номинал облигации, для акций null
- `lot_size`
- `is_active`
- `created_at`

### `operation`

- `id`
- `portfolio_id`
- `asset_id`
- `type` — `BUY` / `SELL`
- `date`
- `quantity` — целое
- `price` — цена в RUB за единицу (для облигаций нормализованная)
- `input_price_type` — `RUB` / `PERCENT` (для облигаций)
- `face_value_at_operation` — номинал на дату операции
- `note`
- `created_at`

### `income`

Единая таблица для дивидендов и купонов.

- `id`
- `portfolio_id`
- `asset_id`
- `kind` — `DIVIDEND` / `COUPON`
- `status` — `EXPECTED` / `PAID`
- `amount_per_unit` — на акцию/облигацию
- `quantity` — количество на дату выплаты
- `amount_total` — итоговая сумма
- `currency` — RUB
- `record_date` — дата фиксации/купонная дата
- `pay_date` — дата выплаты
- `source` — `MOEX` / `MANUAL`
- `external_id` — для дедупликации данных MOEX
- `note`
- `created_at`, `updated_at`

Правила:

- `EXPECTED` допускается только для `COUPON`.
- `DIVIDEND` создается сразу как `PAID` вручную.
- Для купонов MOEX создает `EXPECTED`; пользователь подтверждает выплату и редактирует фактическую сумму.

### `quote`

- `id`
- `asset_id`
- `date`
- `price` — для акций RUB, для облигаций % от номинала
- `price_type` — `RUB` / `PERCENT`
- `source` — `MOEX` / `MANUAL`
- `fetched_at`
- unique(`asset_id`, `date`)

### `portfolio_snapshot`

- `id`
- `portfolio_id`
- `date`
- `market_value`
- `invested`
- `income_paid`
- unique(`portfolio_id`, `date`)

### `app_setting`

- `key`, `value` — настройки обновления, период графика.

## 5. Правила расчетов

### Покупка

```text
new_qty = qty + buy_qty
new_avg = (qty * avg + buy_qty * buy_price) / new_qty
```

Для облигации цена в % переводится в RUB:

```text
price_rub = face_value * price_percent / 100
```

### Продажа

```text
new_qty = qty - sell_qty
avg не меняется
```

Реализованная прибыль не рассчитывается и не показывается.

### Стоимость позиции

- Акция: `qty * last_price`.
- Облигация: `qty * face_value * last_price_percent / 100`.
- Если цена отсутствует: используется последняя известная, позиция помечается как «цена устарела».

### Доходы

- Ожидаемые купоны: `amount_per_unit * current_qty`.
- Фактические дивиденды/купоны: `amount_total` из записи.
- Налоги не вычитаются, суммы gross.
- Дивиденды по акциям не прогнозируются и не подтягиваются автоматически.

### Динамика портфеля

- Для каждой даты: `Σ(qty_at_date * close_price_at_date)` по всем активам.
- `qty_at_date` восстанавливается из операций.
- История цен подтягивается из MOEX с даты первой операции.
- График показывает рыночную стоимость; вложенные средства — отдельная линия/подпись.
- Если история операций неполная, график начинается с первой доступной даты.

## 6. Данные MOEX ISS

Использовать официальный API, без парсинга HTML.

| Данные | Endpoint |
|---|---|
| Поиск бумаг | `GET /iss/securities.json?q={query}` |
| Информация о бумаге | `GET /iss/securities/{secid}.json` |
| Текущая цена | `GET /iss/engines/stock/markets/{market}/boards/{board}/securities/{secid}.json` |
| История цен | `GET /iss/history/engines/stock/markets/{market}/boards/{board}/securities/{secid}.json?from=...&till=...` |
| Купоны и амортизация облигаций | `GET /iss/securities/{secid}/bondization.json` |

Правила:

- Кэшировать ответы в SQLite.
- Обновлять котировки при старте и раз в день после закрытия.
- Ручная кнопка «Обновить данные».
- Retry с backoff, таймаут, User-Agent.
- При недоступности MOEX — работать на последних сохраненных данных, показывать статус.
- Дивиденды акций из MOEX не используем: в MVP только ручные фактические выплаты.
- Для облигаций: купонный график и амортизация из `bondization`; текущий номинал уменьшается по графику амортизации.

- Позиция: количество, средняя, текущая цена, стоимость.

### 7.4 Доходы

- Вкладки «Выплаченные» и «Ожидаемые купоны».
- Фильтры: тип, актив, период.
- Кнопка «Выплачено» с редактированием фактической суммы.
- Добавление фактического дивиденда/купона вручную.

### 7.5 Настройки

- Обновление данных MOEX.
- Статус последнего обновления.
- Экспорт JSON/CSV.

## 10. Критерии приемки

1. Поиск «SBER» находит акцию, добавление создает актив.
2. Покупка 10 @ 100 и 10 @ 120 → 20 шт., средняя 110.
3. Продажа 5 @ 150 → 15 шт., средняя 110.
4. Попытка продать 20 при остатке 15 — ошибка.
5. Облигация с номиналом 1000 и ценой 95% → средняя 950 RUB; отображается и 95%.
6. Ожидаемый купон 35 RUB × 15 облигаций = 525 RUB (если ожидаемые купоны оставлены).
7. Подтверждение купона создает фактическую запись с редактируемой суммой.
8. Фактический дивиденд по акции добавляется вручную и попадает в выплаченный доход.
9. Дашборд: стоимость = сумма стоимостей позиций; выплаченный доход = сумма PAID; ожидаемый доход = сумма EXPECTED купонов.
10. График стоимости строится за выбранный период по историческим ценам MOEX.
11. После перезапуска данные сохраняются.
12. При недоступности MOEX приложение не падает, показывает последние данные.
13. Экспорт JSON/CSV и копия SQLite создаются.

## 11. Тестирование

- Unit: средняя цена, продажа, конвертация цены облигации, сумма купонов, снимок портфеля.
- Unit: парсинг ответов MOEX на сохраненных фикстурах (без сети).
- Integration: API CRUD, подтверждение выплаты, дашборд.
- E2E/ручной сценарий: добавить SBER и ОФЗ → купить → получить купон → увидеть дашборд.
- Проверка границ: нулевая позиция, удаление актива с операциями, отсутствие цены, пустой портфель.

## 12. Риски и ограничения

| Риск | Мера |
|---|---|
| Ожидаемые дивиденды не входят в MVP | Добавить позже отдельным этапом |
| Парсинг сторонних сайтов нестабилен | Не используем; только MOEX ISS |
| НКД не учитывается | Средняя цена — чистая; доходность может быть чуть оптимистичнее. Добавить поле позже |
| Амортизация облигаций | Читаем график MOEX; текущий номинал уменьшается |
| Сплиты акций | Ручная корректировка позиции/операции, автоматизация позже |
| Лимиты MOEX ISS | Кэш, батчи, retry, обновление раз в день |
| История графика неполная | Начинаем с первой операции; прошлые операции можно завести вручную |
| Локальный доступ без пароля | Слушаем только 127.0.0.1; при выходе в сеть — добавить авторизацию |
| Потеря SQLite | Ежедневная копия файла + экспорт |

## 13. Принятые решения

1. **Храним операции покупки/продажи, а не только текущую позицию.**
   Это нужно для средней цены и графика. В интерфейсе показываем только текущую позицию; реализованную прибыль не считаем.
2. **Дивиденды акций — только фактические, вручную.**
   Ожидаемые дивиденды и прогнозы исключены из MVP.
3. **Ожидаемые купоны облигаций — из MOEX.**
   Если они не нужны, этап 4 сокращается.
4. **Цена облигации вводится в % от номинала, хранится и в RUB.**
5. **Один портфель.**
   Без переключателя и управления портфелями.
6. **История графика — с первой операции.**
   Если нужен график за прошлые годы, операции придется завести задним числом.

## 14. Порядок реализации

Проект делится на две последовательные части.

### Часть 1. Backend

- Подробный план: [`docs/BACKEND_PLAN.md`](docs/BACKEND_PLAN.md).
- Результат: работающий REST API, SQLite, интеграция с MOEX ISS, расчеты, тесты, OpenAPI и демо-данные.
- После завершения backend контракт API замораживается, frontend работает только с `/api`.

Порядок:

1. Каркас `backend/`, настройки, миграции, health.
2. Модели `portfolio`, `asset`, `operation`, `income`, `quote`, `bond_amortization`, `portfolio_snapshot`.
3. MOEX-провайдер: поиск, информация, котировки, история, купоны, амортизация.
4. Активы и операции: покупка/продажа, средневзвешенная цена, валидация.
5. Доходы: ожидаемые купоны, подтверждение выплат, ручные дивиденды.
6. Котировки, история, планировщик.
7. Дашборд, snapshots, backup/export.
8. Тесты, OpenAPI, README, seed демо-данных.

### Часть 2. Frontend

- План будет создан отдельным документом после готовности backend API.
- Стек: Angular + PrimeNG + Chart.js.
- Экраны: дашборд, портфель, карточка актива, доходы, настройки.
- Frontend не обращается к MOEX напрямую и не содержит бизнес-расчетов: только отображение и ввод данных.
